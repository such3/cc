    What am I looking at?
    Health check
    A small request the traffic manager sends to each region every interval. Several failures in a row mean the region is unhealthy.
    Failover
    Moving user traffic from the broken primary region to the standby secondary region.
    Failback
    Returning traffic to the primary once it is healthy and has caught up on data.
    RTO (recovery time objective)
    How long users go without service. Lower failure thresholds and faster checks shrink it.
    RPO (recovery point objective)
    How much recent data you can lose. Replication is asynchronous, so the lag you set above is your exposure.
    Why do some requests fail?
    Like real DNS failover, the manager keeps sending traffic to the primary until enough checks fail. Those requests are the cost of detection.
